Card Workspace · Information Architecture

Scope 决定“从哪里取卡片”，Filter 决定“留下哪些卡片”

假设：文件夹、双链与 Card Box 都会替换卡片流的数据源；标签和属性只作用于当前支持筛选的 Scope。下面三种方案均保留 Obsidian 的紧凑树形导航语言。

推荐 · 最小改动

优点：同时可见、迁移成本低。代价：导航较长。

Scope 用唯一左侧标记和底色；Filter 用勾选。用户一眼能看出“替换”与“叠加”。

Card Box 同属 Scope

保持相同的 current-range 状态，只通过 box 图标和规则入口表达“特殊”。

标题只显示 Scope

不要再把标签拼进 scopeText；筛选以 chips 或“2 个筛选”单独显示。

能力禁用要解释原因

某 Scope 不支持标签或属性时，保留分组并禁用，说明是范围能力限制而非空数据。

交互提示：点击任意 Scope 行可观察单选状态；方案 B 的“范围 / 筛选”标签可切换。
