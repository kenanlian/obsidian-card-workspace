# Creating notes, templates and quick input

The top **New note** button creates in the current folder, including the vault root. Selected tags and text, number or boolean property filters become YAML properties. When several values for a property are selected, the first actual value in the complete navigation order is used. A missing-only selection writes no property. Card boxes use **Folder for new notes in card boxes** in the Behavior settings, defaulting to the vault root; links use the most recently visited folder. Both leave paused browsing filters out. In a card box, the button also adds the new note as a manual member of that box. The default new-note template is blank and adds no empty `tags` property; an explicitly configured tags template is still honored.

The **Templates** section appears below Links by default. **New template** asks for a display name and the folder for notes created with the template. The folder input suggests existing vault folders; leave it empty for the vault root. The display name appears in navigation and template choices and does not determine created-note filenames. Creation opens the template in editing mode and selects its initial title. Replace the title to define created-note filenames; edit or delete the initial body guidance (it is actual template content).

To register an existing or synced Markdown file, right-click it in Obsidian's file browser or a Card Workspace card and choose **Set as template**. This option appears for unregistered Markdown files in the configured template storage folder, including subfolders. The same form asks for a template name (prefilled from the filename) and a new-note folder. Applying registers the original file without changing its name or content. If another computer uses a custom storage folder, select that folder in this computer's settings first.

In settings, **Template storage folder** applies to all template files and defaults to `Card Workspace Templates`. Its input suggests vault folders. Press **Apply** or Enter after choosing a path to migrate existing templates, preserving filenames, content, destinations and template choices. Missing storage folders are created automatically. Missing templates or filename conflicts stop migration; files are never overwritten or automatically renamed. Hidden folders are not supported. The row menu edits the file, renames its display name, changes the new-note folder or date/time formats, or deletes the template. **Delete template** uses Obsidian's deletion flow and removes registration after the file is deleted; cancelling keeps the template. If the file is already missing, it removes registration only. Template files appear as ordinary Markdown notes in both Card Workspace and Obsidian's file browser, and participate in search, filters and counts.

Template note titles come from the template filename. An unchanged initial title must be edited before using the template. All `{{date}}` and `{{time}}` tokens in the title and content use one local time snapshot. Characters that cannot appear in filenames become `-`; date slashes do not create folders. Each click reads the latest template, including unsaved editor content. A new target receives the full template. For an existing target, the template body is inserted before opening it, preserving the target's properties and existing text. In the template's row menu, **Insert position in an existing note** selects **Start of body (after properties)** or **End of note** (the default), independently for each template. Template YAML properties are not inserted into an existing note; an empty body simply opens it. Repeated clicks insert the body once per click. Opening a template note keeps the current card scope.

Use `{{date:YYYY-MMMM-DD}}` or `{{time:HH:mm}}` to override the format at a specific position, following Obsidian's Templates syntax. Inline formats accept Moment.js format tokens independently of the row menu's preset formats; `{{date}}` and `{{time}}` still use the template's settings. Empty overrides (`{{date:}}`, `{{time:}}`) also use those settings. All variables share the same local time snapshot.

After creating a note or inserting template content, the note opens in editing mode with the cursor at the end of that content, scrolled into view and ready for typing. For insertion at the start, the cursor is before the original body. Switching notes, typing, or starting another open while work is pending cancels the old automatic positioning.

Use the search icon beside the paper-plane button on the right of the navigation header to expand the independent navigation filter; click again to clear and hide it. The filter uses the card search control's appearance without history suggestions. Its clear button clears the query and keeps focus; Escape keeps the query. The paper-plane button, or the **Open quick input** command, opens a new independent desktop window each time with a blank draft; quick input does not use templates. Several quick-input windows can stay open together, including while the main window is minimized. Opening another focuses only the new draft; existing drafts stay on top by default and keep their independent pin state. Each draft is a compact card with a colored frame: drag the three-dot grip at the top to move it, or resize its edges/corners. The footer shows a folder selector by default. Settings provide five independent visibility switches for title, folder, card boxes, tags and properties; only the folder selector starts enabled. Visibility changes apply to new windows. Clicking elsewhere keeps the draft; Cancel discards it. Enter inserts a newline and Ctrl/Cmd+Enter sends; composition input cannot send accidentally.

The optional title shares the editor scroll area, uses the theme’s inline-title font at a compact size independently of Obsidian’s global title setting, and only sets the filename. It starts empty with this draft’s default filename as its placeholder; a blank title uses that default. Enter moves to the body, which receives initial focus. With the title hidden, timestamp naming uses the send time. The folder and card box buttons open Obsidian’s own search prompt (the same style as the command palette) centered in the draft window. Folder suggestions fuzzy-search all existing folders (including root) sorted by path; arrow keys move, Enter chooses, and the prompt closes and returns focus to the body. Card boxes allow multiple selections: Enter or click toggles a box and keeps the prompt open, Escape finishes, and the button shows the selected count; each draft starts with none, and sending adds the final whole note to the selected boxes without removing existing memberships.

**Add tags** creates or focuses the draft’s native `tags` input. **Add property** and **Ctrl+;** add a native property; the shortcut works even when its button is hidden. Unsupported YAML stays in source form. Properties left completely empty are not saved. With **Append to the existing note** selected, the current folder/title determines **Create** or **Append**; the title is checked once typing pauses, and the send button reads **Append** for an existing note. Append makes draft properties read-only and only inserts the body, preserving the target’s properties; changing back to a new target restores editing and retains draft values. A target that changes between preflight and writing requires another send. If the note saves but box persistence fails, the draft reports its saved path and retry only completes the box step. Targets and content remain locked during pending or uncertain retries.

Drafts with ordinary frontmatter show Obsidian’s native Properties editor above the body, in the same scroll area. Text, number, checkbox, date, tag and text-list values can be edited directly. The heading aligns with the property names. Nested values, non-text lists, anchors/aliases, invalid YAML or an unavailable native panel stay in source form. Editing properties retains comments and scalar styles, although YAML spacing may be normalized. Draft values are only written when sent; changing a property type follows Obsidian’s vault-wide type settings. Sending commits the active property input and locks both properties and body, including while a failed request is kept for retry. Links in an unsaved draft resolve from the vault root.

Each send saves into the configured quick-input folder or the folder chosen in the draft. Without a typed title, filenames use `quick-note YYYY-MM-DD HH-mm-ss`, e.g. `quick-note 2026-10-17 14-30-05.md`, with numbering for collisions. When the title names a note that already exists in that folder, **When the title already exists** in settings decides what happens: **Append to the existing note** inserts the edited draft body and preserves the note’s own properties and content; **Create a new note with a number** creates e.g. `Title 1.md`; **Ask each time** (the default) shows a dialog on send with both choices, and cancelling keeps the draft. **Append position** chooses the start of the body (after YAML properties) or the end of the note, and is hidden when same-name notes are always numbered. New notes keep the order shown in the draft. Tokens typed in your draft are kept literally. Success closes the draft and shows its saved path without opening the note. Each window starts from a snapshot of the destination settings; changes to its title, folder and boxes stay with that draft. Later global settings changes apply to new windows. A failed submission retains the exact draft and captured configuration for retry; Cancel releases that draft. Missing references block sending.

Settings also set the size of each new draft (default 480 × 400 pixels) and its frame color: **Random** picks a theme color different from the previous draft, or choose the accent color or one fixed color. Quick-input windows use the plugin’s own card interface and appear after their editor and styles are ready. On Windows, transparency and disabled system decorations let the card draw its corner radius; its edges and corners resize through the card’s own handles. Windows visual acceptance and other desktop platforms still require the host checks below. Resizing a draft only affects that draft; new windows use the configured size on the source window’s screen, or the mouse’s screen for the global shortcut, cascading within its work area.

Quick input requires **Obsidian frame** or **Hidden frame** under Settings → Appearance → Window frame style. After changing it, fully restart Obsidian. System native frames are blocked with instructions; the plugin does not change this setting. Missing desktop capabilities also block opening.

**Global quick input shortcut** is empty by default. Record a combination or enter an Electron accelerator, then click **Apply** to register and save it. Typing alone does not register it. A conflicting or invalid replacement leaves the old binding and saved configuration intact. Startup registration failures preserve the saved combination and appear in the settings status. **Clear** unregisters this vault’s binding and saves an empty value. If saving fails, the status lists all currently active bindings; Apply retries saving, and a replacement releases the old binding only after saving succeeds.

The pin button at the bottom left, before the destination, keeps only that window on top. It starts on for every new window and is never saved; click it to turn pinning off for that window. The top contains only the drag grip; use Cancel to discard a draft. Closing through the operating system also discards unsent input; drafts, window positions and pins do not survive restart. Sending disables repeat-send and cancel; closing a window through the operating system during a send lets the submitted write finish. Successful sends close only their own window. Closing the vault, unloading the plugin or quitting Obsidian closes its quick-input windows. macOS application hiding, Spaces and fullscreen coverage are outside the pin guarantee; Linux runs by capability detection without a Wayland experience guarantee.

Quick input uses an internal native Markdown editor capability adapter. If the host does not provide compatible capabilities, opening shows a message. Automated tests and isolated Linux hosts cover the adapter and window lifecycle; Windows/macOS appearance, physical IME and global-shortcut activation still require verification. See the [validation record](quick-input-validation.md).

# 笔记创建、模板与快速输入

顶部“新建笔记”在当前文件夹创建，包括仓库根目录，并继承选中标签及文本、数字、布尔属性筛选。同一属性多选时取完整导航排序中第一个实际值；仅选“缺失”时不写该属性。卡片盒使用“行为”设置中的“卡片盒新建笔记保存位置”，默认为仓库根目录；链接范围使用最近浏览的文件夹。两者均不继承暂停的筛选。卡片盒中也显示此按钮，创建后将笔记手动加入该卡片盒。新建笔记模板默认为空白，不添加空的 `tags` 属性；已明确设置的标签模板仍会保留。

“模板”区默认位于双链下方。“新建模板”填写模板名称和新建笔记文件夹，文件夹输入框提供已有仓库文件夹建议，留空表示仓库根目录。模板名称用于导航和模板选择，不作为生成笔记的文件名。创建后直接进入模板编辑模式，并选中初始标题。修改标题来定义生成笔记的文件名；正文引导行属于实际内容，若希望正文为空，请删除该行。

已有或同步过来的 Markdown 文件可在 Obsidian 文件浏览器或插件卡片中右键选择“设置为模板”。此选项仅对当前模板存储文件夹（含子文件夹）内尚未注册的 Markdown 文件显示。弹窗与新建模板共用，模板名称默认填写文件名，同时设置新建笔记文件夹；点击“应用”后直接注册原文件，保留文件名和正文。若另一台电脑使用自定义模板存储文件夹，请先在本机设置中选中对应文件夹。

设置中的“模板存储文件夹”统一应用于所有模板，默认 `Card Workspace Templates`，同样提供输入框和文件夹建议。选好路径后点击“应用”或按 Enter，现有模板自动迁移，保留文件名、正文、笔记目标文件夹和模板选择；存储目录不存在时自动创建。模板丢失或存在同名冲突时停止迁移，不覆盖文件、不自动改名。不支持隐藏目录。行菜单可编辑模板、重命名导航名称、修改新建笔记文件夹和日期／时间格式，以及删除模板。“删除模板”遵循 Obsidian 的删除流程，文件删除后再移除模板配置；取消删除时保留模板。文件已丢失时只移除配置。模板文件作为普通 Markdown 笔记显示在插件卡片与 Obsidian 文件浏览器中，并正常参与搜索、筛选和数量统计。

目标标题来自模板文件名，初始标题未修改时会提示先编辑；标题及正文中的全部 `{{date}}`、`{{time}}` 使用同一个本地时间快照。文件名禁用字符替换为 `-`，日期中的 `/` 不生成文件夹。每次点击都会读取最新模板，包括编辑器中尚未保存的内容。目标不存在时使用完整模板创建；目标已存在时，先插入模板正文再打开，保留笔记原有属性和内容。右键模板，在“同名笔记插入位置”下选择“正文开头（属性之后）”或“笔记末尾”（默认），每个模板可分别设置。模板的 YAML 属性不重复插入已有笔记；模板正文为空时仅打开笔记。连续点击会每次插入一次正文。打开后保持卡片范围。

可使用 `{{date:YYYY-MMMM-DD}}`、`{{time:HH:mm}}` 在具体位置覆盖格式，语法与 Obsidian 官方“模板”插件一致。冒号后的格式支持 Moment.js 格式标记，不受行菜单预设格式的限制；普通 `{{date}}`、`{{time}}` 仍使用模板设置。空格式（`{{date:}}`、`{{time:}}`）也使用模板设置。全部变量共用同一个本地时间快照。

创建笔记或插入模板正文后，笔记自动进入编辑模式，光标停在本次正文末尾，并滚动到可见位置，可直接继续输入。选择开头插入时，光标位于新增正文之后、原有正文之前。等待期间切换笔记、输入内容或发起新的打开操作，会取消旧请求的自动定位。

导航顶部右侧、纸飞机旁的搜索图标展开独立导航筛选，再次点击清空并收起。搜索框沿用卡片搜索的样式，不提供历史建议；清除按钮清空查询并保留焦点，Escape 保留查询。最右侧纸飞机或“打开快速输入”命令每次打开一个新的空白草稿；快速输入不使用模板。每个草稿使用独立的桌面窗口，可同时打开多个；主窗口最小化后仍可输入和发送。再次打开时，焦点落在新草稿；每个草稿默认置顶，已有草稿保持各自的置顶状态。草稿是带彩色边框的小卡片：拖动顶部三点手柄移动，拖动边角调整大小。底部默认显示文件夹选择。设置提供标题、文件夹、卡片盒、标签、属性五项独立可见性开关，默认仅显示文件夹；可见性变更仅影响之后打开的窗口。失焦保留，取消丢弃。Enter 换行，Ctrl/Cmd+Enter 发送，输入法组合期间不发送。

可选标题位于编辑区域顶部，与属性和正文共用滚动区域，沿用主题内联标题字体并缩小字号，不依赖 Obsidian 全局标题开关，且只决定文件名。标题初始为空，以本草稿默认文件名作为占位提示，留空即使用默认文件名；Enter 进入正文，首次打开仍聚焦正文。隐藏标题时沿用发送时的时间戳命名。文件夹和卡片盒按钮打开 Obsidian 原生搜索弹框（与命令面板同款），居中显示在草稿窗口内。文件夹建议按路径排序、模糊搜索所有已有文件夹（含仓库根目录），方向键移动、Enter 选择，选择后关闭弹框并回到正文。卡片盒支持多选：Enter 或点击切换选中且弹框保持打开，Esc 完成选择，按钮显示已选数量，每个新草稿默认不选；发送后将最终整篇笔记加入所选盒子，不会移除已有成员关系。

“添加标签”创建或聚焦草稿的原生 `tags` 输入。“添加属性”和 **Ctrl+;** 执行同一属性添加操作，按钮隐藏时快捷键仍有效。复杂或无效 YAML 保留源码编辑，完全为空的属性区不会写入笔记。“标题与已有笔记同名时”设为“追加到该笔记”时，按当前文件夹和标题判断“新建”或“追加”，标题在停止输入后判断，同名笔记已存在时发送按钮显示为“追加”；追加时草稿属性只读，仅插入正文并保留目标原有属性。改回新目标后恢复属性编辑并保留草稿值。若发送预检与写入时的目标状态不同，需要再次发送。笔记已保存但盒子持久化失败时，会提示已保存路径，重试只完成盒子步骤。发送或不确定保存结果的重试期间，目标和内容均保持锁定。

草稿包含普通 frontmatter 时，正文上方会显示 Obsidian 原生属性编辑器，两者共用滚动区域，可直接编辑文本、数字、复选框、日期、标签和文本列表。“笔记属性”标题与下方属性名称对齐。嵌套属性、非文本列表、锚点/别名、无效 YAML 或原生面板不可用时，保留源码编辑。属性修改会保留注释及标量样式，YAML 空白格式可能被规范化。草稿属性值只在发送时写入；修改属性类型沿用 Obsidian 的仓库级类型设置。发送会先提交当前属性框的输入，再锁定属性和正文；失败后等待重试的草稿也保持锁定。未保存草稿中的链接从仓库根目录解析。

每次发送保存到设置中的快速输入文件夹或草稿中选择的文件夹。未填写标题时文件名为 `quick-note YYYY-MM-DD HH-mm-ss`，如 `quick-note 2026-10-17 14-30-05.md`，重名时添加编号。标题与该文件夹中已有笔记同名时，按设置中的“标题与已有笔记同名时”处理：“追加到该笔记”插入编辑后的草稿正文，保留原有属性与内容；“新建笔记并在名称后加数字”创建如 `标题 1.md` 的新笔记；“每次询问”（默认）在发送时弹窗选择，取消则保留草稿。“追加位置”可选正文开头（YAML 属性之后）或笔记末尾，同名笔记始终新建时隐藏。新建笔记保持草稿中显示的顺序。输入中的变量文本不替换。每个窗口从打开时的目标设置开始，修改当前标题、文件夹、盒子不会改全局设置；之后修改全局设置会应用于新窗口。发送成功关闭并提示保存位置，不打开目标笔记；失败保留草稿及本次固定配置供重试，取消可释放草稿。引用缺失时禁止发送。

设置还可调整新草稿的窗口大小（默认 480 × 400 像素）和边框颜色：“随机”每次选用与上一个草稿不同的主题颜色，也可选择强调色或固定颜色。快速输入使用插件自绘界面，编辑器与样式就绪后再显示；Windows 通过透明背景并关闭系统装饰，由卡片绘制圆角、由自身边角手柄调整大小。Windows/macOS 的实际外观仍需实机验收。拖拽调整只影响当前草稿；普通入口在来源窗口所在屏幕定位，全局快捷键在鼠标所在屏幕定位；同屏窗口错位排列并限制在工作区内。

快速输入要求在“设置 → 外观 → 窗口框架样式”中使用 **Obsidian 框架** 或 **隐藏框架**，切换后必须完全重启 Obsidian。系统原生框架下会阻止打开并提示手动切换，插件不会修改宿主设置。所需桌面能力缺失时同样阻止打开。

“快速输入全局快捷键”默认留空。录入组合键或填写 Electron 快捷键格式后，点击“应用”才会尝试注册并保存；仅输入不会注册。新组合无效或被占用时保留原绑定和已保存配置。启动注册失败会保留配置并在设置页显示失败状态。“清除”释放本仓库拥有的绑定并保存空值。保存失败时状态显示全部生效绑定；点击“应用”重试保存，替换成功保存后才释放原绑定。从其他软件调用只显示并聚焦新的速记窗口，不主动恢复主窗口。

左下角、目标位置信息前的置顶按钮仅影响当前窗口，每次新建默认开启，可点击取消当前窗口的置顶，不持久化。顶部仅保留拖动手柄，点击“取消”丢弃草稿。通过系统关闭窗口也会丢弃未发送草稿；草稿、位置、置顶均不跨重启保存。发送期间禁用重复发送和取消；通过系统关闭窗口后，已提交写入仍继续完成。成功仅关闭对应窗口。仓库关闭、插件卸载或 Obsidian 退出时关闭所属速记窗口。macOS 隐藏整个应用、跨桌面空间及覆盖全屏应用不属于置顶保证；Linux 按能力检测运行，不承诺 Wayland 的置顶和全局快捷键体验。

原生 Markdown 编辑器使用独立的内部能力兼容适配层，宿主能力不兼容时提示不可用。自动测试和隔离 Linux 宿主覆盖适配接口及窗口生命周期；Windows/macOS 实际验收仍待执行，详见[验收记录](quick-input-validation.md)。

移动端快速输入使用 Obsidian Modal，手机全屏、平板居中；同一插件实例只有一个移动草稿。非空已修改草稿关闭时需要确认，发送中保持界面，失败后冻结原请求重试。缺少原生编辑能力时保留完整 Markdown 源码输入。详见 [移动端说明](mobile.md)。
