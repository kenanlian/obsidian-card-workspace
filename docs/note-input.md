# Creating notes, templates and quick input

The top **New note** button creates in the current folder, including the vault root. Selected tags and text, number or boolean property filters become YAML properties. When several values for a property are selected, the first actual value in the complete navigation order is used. A missing-only selection writes no property. Boxes and links use the most recently visited folder and leave paused browsing filters out.

The **Templates** section appears below Links by default. **New template** asks for a display name and the folder for notes created with the template. The folder input suggests existing vault folders; leave it empty for the vault root. The display name appears in navigation and template choices and does not determine created-note filenames. Creation opens the template in editing mode and selects its initial title. Replace the title to define created-note filenames; edit or delete the initial body guidance (it is actual template content).

In settings, **Template storage folder** applies to all template files and defaults to `Card Workspace Templates`. Its input suggests vault folders. Press **Apply** or Enter after choosing a path to migrate existing templates, preserving filenames, content, destinations and template choices. Missing storage folders are created automatically. Missing templates or filename conflicts stop migration; files are never overwritten or automatically renamed. Hidden folders are not supported. The row menu edits the file, renames its display name, changes the new-note folder or date/time formats, or removes registration without deleting the file. Registered files remain accessible in Obsidian's file browser and are excluded from Card Workspace cards and their counts.

Template note titles come from the template filename. An unchanged initial title must be edited before using the template. All `{{date}}` and `{{time}}` tokens in the title and content use one local time snapshot. Characters that cannot appear in filenames become `-`; date slashes do not create folders. Clicking again when the target exists opens that note without overwriting it. Opening a template note keeps the current card scope.

Use the search icon beside the paper-plane button on the right of the navigation header to expand the independent navigation filter; click again to clear and hide it. The filter uses the card search control's appearance without history suggestions. Its clear button clears the query and keeps focus; Escape keeps the query. The paper-plane button, or the **Open quick input** command, opens a new independent desktop window and blank draft each time. Several quick-input windows can stay open together, including while the main window is minimized. Opening another focuses only the new draft; existing drafts follow normal desktop window stacking and keep their independent pin state. Each draft is a compact card with a colored frame: drag the three-dot grip at the top to move it, or resize its edges/corners. The bottom of the frame shows `Location · Inbox` without a template (`Location · Vault root` for the root), or `Template · Daily` with a template, using its display name. It turns into a warning when the destination is unavailable. Clicking elsewhere keeps the draft; Cancel discards it. Enter inserts a newline and Ctrl/Cmd+Enter sends; composition input cannot send accidentally.

In settings, **No template (new note each time)** creates a separate note for every send in the configured quick-input folder. Filenames use `quick-note YYYY-MM-DD HH-mm-ss`, e.g. `quick-note 2026-10-17 14-30-05.md`, with numbering for collisions. With a template, its destination folder and filename determine the target: a new target receives the template and your input; an existing target receives only your input. For example, `{{date}}.md` with the `YYYY-MM-DD` date format collects a day's inputs in one note, while including time in the filename can create separate notes. **Body insert position** appears only when a template is selected. Choose the start of the body (after YAML properties) or the end of the note; this applies to both the template body when creating a note and the current body of an existing note. Tokens typed in your draft are kept literally. Success closes the draft and shows its saved path without opening the note. A failed submission retains the exact draft and captured configuration for retry; Cancel releases that draft. Missing references block sending.

Settings also set the size of each new draft (default 480 × 270 pixels) and its frame color: **Random** picks a theme color different from the previous draft, or choose the accent color or one fixed color. Quick-input windows use the plugin’s own card interface and appear after their editor and styles are ready. On Windows, transparency and disabled system decorations let the card draw its corner radius; its edges and corners resize through the card’s own handles. Windows visual acceptance and other desktop platforms still require the host checks below. Resizing a draft only affects that draft; new windows use the configured size on the source window’s screen, or the mouse’s screen for the global shortcut, cascading within its work area.

Quick input requires **Obsidian frame** or **Hidden frame** under Settings → Appearance → Window frame style. After changing it, fully restart Obsidian. System native frames are blocked with instructions; the plugin does not change this setting. Missing desktop capabilities also block opening.

**Global quick input shortcut** is empty by default. Record a combination or enter an Electron accelerator, then click **Apply** to register and save it. Typing alone does not register it. A conflicting or invalid replacement leaves the old binding and saved configuration intact. Startup registration failures preserve the saved combination and appear in the settings status. **Clear** unregisters this vault’s binding and saves an empty value. If saving fails, the status lists all currently active bindings; Apply retries saving, and a replacement releases the old binding only after saving succeeds.

The pin button at the bottom left, before the destination, keeps only that window on top. It starts off for every new window and is never saved. The top contains only the drag grip; use Cancel to discard a draft. Closing through the operating system also discards unsent input; drafts, window positions and pins do not survive restart. Sending disables repeat-send and cancel; closing a window through the operating system during a send lets the submitted write finish. Successful sends close only their own window. Closing the vault, unloading the plugin or quitting Obsidian closes its quick-input windows. macOS application hiding, Spaces and fullscreen coverage are outside the pin guarantee; Linux runs by capability detection without a Wayland experience guarantee.

Quick input uses an internal native Markdown editor capability adapter. If the host does not provide compatible capabilities, opening shows a message. Automated tests and isolated Linux hosts cover the adapter and window lifecycle; Windows/macOS appearance, physical IME and global-shortcut activation still require verification. See the [validation record](quick-input-validation.md).

# 笔记创建、模板与快速输入

顶部“新建笔记”在当前文件夹创建，包括仓库根目录，并继承选中标签及文本、数字、布尔属性筛选。同一属性多选时取完整导航排序中第一个实际值；仅选“缺失”时不写该属性。盒子、链接范围使用最近浏览的文件夹，不继承暂停的筛选。

“模板”区默认位于双链下方。“新建模板”填写模板名称和新建笔记文件夹，文件夹输入框提供已有仓库文件夹建议，留空表示仓库根目录。模板名称用于导航和模板选择，不作为生成笔记的文件名。创建后直接进入模板编辑模式，并选中初始标题。修改标题来定义生成笔记的文件名；正文引导行属于实际内容，若希望正文为空，请删除该行。

设置中的“模板存储文件夹”统一应用于所有模板，默认 `Card Workspace Templates`，同样提供输入框和文件夹建议。选好路径后点击“应用”或按 Enter，现有模板自动迁移，保留文件名、正文、笔记目标文件夹和模板选择；存储目录不存在时自动创建。模板丢失或存在同名冲突时停止迁移，不覆盖文件、不自动改名。不支持隐藏目录。行菜单可编辑模板、重命名导航名称、修改新建笔记文件夹和日期／时间格式，以及取消登记。登记文件从插件卡片与数量统计中排除，仍可从 Obsidian 文件浏览器访问。取消登记保留原文件。

目标标题来自模板文件名，初始标题未修改时会提示先编辑；标题及正文中的全部 `{{date}}`、`{{time}}` 使用同一个本地时间快照。文件名禁用字符替换为 `-`，日期中的 `/` 不生成文件夹。目标已存在时直接打开，不覆盖内容；打开后保持卡片范围。

导航顶部右侧、纸飞机旁的搜索图标展开独立导航筛选，再次点击清空并收起。搜索框沿用卡片搜索的样式，不提供历史建议；清除按钮清空查询并保留焦点，Escape 保留查询。最右侧纸飞机或“打开快速输入”命令每次打开一个新的空白草稿，每个草稿使用独立的桌面窗口，可同时打开多个；主窗口最小化后仍可输入和发送。再次打开时，已有速记一起回到入口窗口前方，焦点落在新草稿；长期置顶仍由各自按钮控制。草稿是带彩色边框的小卡片：拖动顶部三点手柄移动，拖动边角调整大小。边框底部无模板时显示“位置 · Inbox”（根目录显示“位置 · 仓库根目录”），有模板时显示模板名称，如“模板 · 每日记录”；目标不可用时变为警告提示。失焦保留，取消丢弃。Enter 换行，Ctrl/Cmd+Enter 发送，输入法组合期间不发送。

设置中选择“不使用模板（每次新建笔记）”时，每次发送都会在快速输入文件夹中新建一篇独立笔记，文件名为 `quick-note YYYY-MM-DD HH-mm-ss`，如 `quick-note 2026-10-17 14-30-05.md`，重名时添加编号。使用模板时，保存文件夹和文件名由模板决定；目标不存在则合成模板与输入创建，目标已存在则仅插入本次输入。例如，`{{date}}.md` 配合 `YYYY-MM-DD` 日期格式可将同一天的输入汇集到一篇笔记；文件名包含时间可用于分别创建笔记。“正文插入位置”仅在选择模板时显示，可选正文开头（YAML 属性之后）或笔记末尾，新建时相对于模板正文插入，已有笔记则相对于已有正文插入。输入中的变量文本不替换。发送成功关闭并提示保存位置，不打开目标笔记；失败保留草稿及本次固定配置供重试，取消可释放草稿。引用缺失时禁止发送。

设置还可调整新草稿的窗口大小（默认 480 × 270 像素）和边框颜色：“随机”每次选用与上一个草稿不同的主题颜色，也可选择强调色或固定颜色。快速输入使用插件自绘界面，编辑器与样式就绪后再显示；Windows 通过透明背景并关闭系统装饰，由卡片绘制圆角、由自身边角手柄调整大小。Windows/macOS 的实际外观仍需实机验收。拖拽调整只影响当前草稿；普通入口在来源窗口所在屏幕定位，全局快捷键在鼠标所在屏幕定位；同屏窗口错位排列并限制在工作区内。

快速输入要求在“设置 → 外观 → 窗口框架样式”中使用 **Obsidian 框架** 或 **隐藏框架**，切换后必须完全重启 Obsidian。系统原生框架下会阻止打开并提示手动切换，插件不会修改宿主设置。所需桌面能力缺失时同样阻止打开。

“快速输入全局快捷键”默认留空。录入组合键或填写 Electron 快捷键格式后，点击“应用”才会尝试注册并保存；仅输入不会注册。新组合无效或被占用时保留原绑定和已保存配置。启动注册失败会保留配置并在设置页显示失败状态。“清除”释放本仓库拥有的绑定并保存空值。保存失败时状态显示全部生效绑定；点击“应用”重试保存，替换成功保存后才释放原绑定。从其他软件调用只显示并聚焦新的速记窗口，不主动恢复主窗口。

左下角、目标位置信息前的置顶按钮仅影响当前窗口，每次新建默认关闭，不持久化。顶部仅保留拖动手柄，点击“取消”丢弃草稿。通过系统关闭窗口也会丢弃未发送草稿；草稿、位置、置顶均不跨重启保存。发送期间禁用重复发送和取消；通过系统关闭窗口后，已提交写入仍继续完成。成功仅关闭对应窗口。仓库关闭、插件卸载或 Obsidian 退出时关闭所属速记窗口。macOS 隐藏整个应用、跨桌面空间及覆盖全屏应用不属于置顶保证；Linux 按能力检测运行，不承诺 Wayland 的置顶和全局快捷键体验。

原生 Markdown 编辑器使用独立的内部能力兼容适配层，宿主能力不兼容时提示不可用。自动测试和隔离 Linux 宿主覆盖适配接口及窗口生命周期；Windows/macOS 实际验收仍待执行，详见[验收记录](quick-input-validation.md)。
